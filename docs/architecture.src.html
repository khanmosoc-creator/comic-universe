01 · System

Architecture

Everything a reader needs is produced at build time. Content and art are authored offline by the owner, committed to GitHub, built by Cloudflare Pages and served as static files from Cloudflare's edge. The reader's browser only ever talks to the site's own origin.

02 · Requests

Routing & request flow

The build contains no 404.html, so Cloudflare Pages runs in single-page-app mode: a real file is served as-is, and any other path returns index.html, where a 60-line History-API router renders the page. No catch-all _redirects rule exists, so assets are never rewritten.

04 · Data

Content model

All comic content is static JSON in apps/web/src/content/, typed by src/types.ts and bundled at build time. The optional Java API packages the same files, so the contract stays single-sourced.

universe.jsonLore, map, places, code, timeline{ intro, map, places[], code, timeline[] }
gallery.jsonArt Vault entriesitems[]: { id, title, src, fallback, width, height, alt, note, usedIn }

To add Issue #2: create issue-002.json with the same shape, import it in src/lib/content.ts (append to issues), and add it to ISSUE_FILES in the Java repository class.

05 · Art

Art pipeline & approvals

The five owner sketches appear in panels 3, 4, 5, 7 and 8 and in the Art Vault. They were flattened, trimmed, resized to 1600 px and re-encoded as WebP with PNG fallbacks, with all metadata removed. The 20 studio images (portraits, cover, seven panels, banner, map, badge, social card) are hand-coded vector drawings from tools/art/generate_art.py; lettering is outlined from the bundled Poppins font so nothing depends on fonts at runtime.

  1. PrepareRun process_owner_art.py for sketches or generate_art.py for studio art.
  2. ReviewOwner checklist in docs/art-approval-workflow.md: original, kid-appropriate, no child photos or identifying details, rights held, alt text written.
  3. RecordAdd the file, hash, source, rights and approval date to docs/asset-manifest.json.
  4. PublishPull request → CI build → Cloudflare preview URL → owner sign-off → merge to main.
06 · Children & families

Privacy & compliance

Privacy-by-design: the site has nothing that collects information from readers, sets no cookies, uses no browser storage and makes no third-party requests. A strict CSP (default-src 'self') enforces that, and CI fails the build if an external URL appears in the output.

AreaFindingStatus
Reader data collectionNo accounts, forms, comments, uploads, chat, newsletter, analytics, ads or social embedsVerified
Hosting processingCloudflare receives standard request data (IP, user agent, URL, time) to deliver and protect the site; disclosed on /privacyDisclosed
Cloudflare Web AnalyticsNot enabled; leave it off in the Pages project's Metrics tabOwner to confirm
COPPA (amended Rule, compliance date Apr 22, 2026)Persistent identifiers only for support of internal operations by the host; no other personal information collectedLegal review
Business contact on /privacyNone invented; the policy says one will be addedOwner action
US state children's privacy lawsTriggers (data processing, profiling, social features) are absentLegal review
Sketch rights & guardian consentNo artist name or age published; owner to confirm rights and consent for commercial useOwner action
Trademark clearance"Super Zayd's Maze Guardians" and character names not yet searchedLegal review

This is an engineering review, not legal advice, and it does not guarantee compliance. The full checklist, including which future features need a fresh review (accounts, payments, email, comments, analytics, ads, a public API), is in docs/privacy-compliance-checklist.md.

07 · Quality

Accessibility & security

  • WCAG 2.2 AA target: landmarks, one h1 per page, skip link, visible focus, focus moved to <main> on navigation, keyboard-operable reader with a live "Panel N of 12" announcement.
  • All images have alt text; dialogue is real text below each panel, not baked into images; reduced-motion respected; targets ≥ 24 px; tested at 375 px wide with no horizontal scroll.
  • Headers (public/_headers): CSP, Referrer-Policy: no-referrer, X-Content-Type-Options, X-Frame-Options: DENY, COOP, restrictive Permissions-Policy, HSTS; hashed assets cached for a year.
08 · Hands-on

Run it locally

  1. Clone
    git clone https://github.com/khanmosoc-creator/comic-universe.git
cd comic-universe/apps/web
  2. Install (Node 22)
    npm ci
  3. Develop
    npm run dev        # http://localhost:5173
  4. Check and build
    npm run check      # tsc --noEmit + vite build → dist/
npm run preview    # serve the production build
  5. Regenerate art (optional, Python 3.10+ with Pillow and fontTools)
    cd ../..
python3 tools/art/generate_art.py apps/web/public/art

11 · Future

Java backend (optional)

services/api is a Java 21 / Spring Boot 3.5 read-only content API with the contract in docs/api/openapi.yaml. It is stateless (no sessions, cookies or access logs), keeps CORS closed unless COMIC_CORS_ALLOWED_ORIGINS is set, and is tested in api-ci. The public site neither builds against it nor calls it.

cd services/api
mvn verify                 # tests
mvn spring-boot:run        # http://localhost:8080/api/v1/issues/issue-1

Path to a commercial platform: keep the static reader on Pages; host the API (for example on AKS or Azure Container Apps) behind APIM for partner feeds; add a CMS or database behind ContentRepository; and only then add accounts, purchases or newsletters, each after a new COPPA and state-law review with verifiable parental consent where required. Upgrade to Spring Boot 4.x before production.

12 · Money

Cost & limits

$0 per month. Cloudflare Pages Free serves static assets without charging for requests or bandwidth. The limits that matter: 500 builds a month, one build at a time, a 20-minute build timeout, 20,000 files per site and 25 MiB per file. This site is about 70 files (~2 MB) and builds in roughly a minute. GitHub Actions minutes are free for public repositories.
